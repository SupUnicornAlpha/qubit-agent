# Qubit 量化研究环境升级路线图

目标是让研究员和不同 Agent 在同一套可追溯环境中，持续完成因子研究、策略构建、验证和资产管理。可用的研究产物应有明确的数据、版本、适用条件与验证证据；本路线图不把一次高 IC 或回测盈利等同于策略可交易。

本轮已实现第 1、2 步的软件能力：可信数据检查、受控研究协议、持久实验台账、独立封存评估服务与研究管理界面。真实市场的严格验证仍需管理员提供可信来源数据并部署隔离评估服务；当前开发环境未配置该服务，不会显示正式验证可用。第 3 至第 6 步是后续建设范围。

## 推进顺序

| 步骤 | 交付结果 | 主要验收问题 |
| --- | --- | --- |
| 1. 可信数据基础 | 同一冻结快照上的计算、时点检查、截断一致性证据 | 加入未来数据会不会改变过去信号？缺证据会不会被当作已验证？ |
| 2. 受控研究项目与实验台账 | 协议版本、所有尝试、跨会话预算、封存评估权限 | 改名字、换 Agent 或新建回测能否重置研究历史与测试额度？ |
| 3. 因子增量评估 | 表达式、信号、收益、组合四层比较 | 候选相对已有研究资产增加了什么？ |
| 4. 因子到策略闭环 | 从假设、因子到组合、成本、执行约束的可复现产物 | 优势在可执行的策略中是否仍成立？ |
| 5. 统一资产管理 | 因子、策略、实验、证据的版本关系与状态规则 | 结果能否复核、复用、回退和退役？ |
| 6. 模拟运行与持续验证 | 同码模拟运行、差异定位、失效监控 | 历史研究结果能否在持续运行中兑现？ |

首个完整验收场景收敛为一个市场、日频、一个因子研究流程。第 1 步代码中的截断检查仅支持日频 `qlib_expr`；市场选择仍沿用现有项目和数据来源配置，并没有新增“所有市场均已验证”的保证。

## 已有基础与真实缺口

仓库已具备市场快照、快照绑定、PIT 审计、财务数据按可用时间映射、因子注册与计算、因子评估、研究合同、相关性与暴露诊断、策略版本与组合、回测、walk-forward、final holdout、模拟运行及晋级检查。升级应连接并加强这些能力，避免再造第二套因子库或回测引擎。

现有能力的名称不能代替执行边界：

- `FactorService.autoEvaluate` 中按日期划分的样本内/样本外报告保留了切分和标签隔离信息，但研究者仍可能反复观察并据此改动候选。它不等于有独立权限控制的封存评估。
- `FinalHoldoutEvaluationService` 当前防重复逻辑按 `backtestRunId` 查询已用 holdout。它能限制同一回测的重复使用，尚不能阻止通过新回测、新策略名或另一会话重新接触同一测试窗口。
- 冻结一份数据只固定了输入。今天取得、按历史日期排列的数据，未必证明当年就已公开，历史成分与复权信息也需要单独证据。
- 已有因子相关性和暴露诊断是第 3 步的基础，高相关不直接代表无价值，低相关也不直接代表创新。

## 第 1 步：可信数据基础（已实现）

### 实际交付

1. **固定研究输入。** 在因子工作台选择或冻结日线快照；计算、自动评估及绑定快照的因子值预览使用同一 `datasetSnapshotId`。结果携带快照、来源、表达式指纹、区间与数据资格。
2. **修正未知证据的含义。** 数据时点证据缺失时保留 `unknown` / `not_verified`，允许符合结构要求的数据用于研究，但不再仅因时间戳早于 `asOf` 就默认获得严格 PIT 资格。
3. **检查可识别的时点错误。** 沿用并加强 PIT 审计，检查数据边界、时间戳、顺序、重复、OHLCV 以及可用事件证据；明确区分发现违规与证据不足。
4. **截断一致性。** 对日频 `qlib_expr`，分别计算完整输入和按若干日期截断的输入，比较截止日及以前同标的、同日期信号。出现数值变化或单侧缺失时记为失败；双侧缺失和 warmup 不当作通过样本。负滞后的 `Ref` / `Delta` 直接判为未来依赖。
5. **计算前执行。** 绑定快照的因子计算会先检查数据完整性；明确失败时，在调用计算 Provider 和写入因子值之前拒绝。证据不足或尚不支持的检查只能形成研究结果，不能包装成验证通过。
6. **保留可查看证据。** 计算元信息返回 `dataIntegrity`；自动评估把对应证据带入评估报告，工作台展示检查状态、来源、区间、截断点与限制。独立检查接口用于先查看问题，而不需要先成功计算。

### 工作台使用

1. 在因子工作台选定因子、标的和研究日期区间。
2. 在“研究数据快照（日线）”中粘贴已有快照 ID，或点击“冻结所选数据”。本轮快捷冻结最多 500 根日线，并为收益标签预留后续数据；覆盖不足时应调整区间或使用覆盖足够的已有快照。
3. 点击“检查时点与前视依赖”，查看“数据检查通过”“仅供研究 · 证据未齐”或失败原因。
4. 使用同一快照计算和评估，查看当前结果及评估记录中的数据证据。修改快照、标的或日期后重新检查，旧报告不能作为新上下文的证据。

没有绑定快照的旧入口仍可能用于自由探索；这条路径不构成受控研究验证。严禁把自由探索与快照验证的结果在展示或晋级时混为一谈。

### API 使用

已有因子和快照时，先调用独立检查接口：

```http
POST /api/v1/factors/{factorId}/data-integrity
Content-Type: application/json
```

```json
{
  "datasetSnapshotId": "<已有的 mkt_snapshot_ 开头的快照 ID>",
  "symbols": ["600000", "600519"],
  "startDate": "2025-01-01",
  "endDate": "2025-06-30"
}
```

示例中的快照 ID 必须替换为实际存在且覆盖请求标的和区间的快照。接口返回的 `data.status` 为：

| 状态 | 含义 | 后续处理 |
| --- | --- | --- |
| `passed` | 当前快照资格、PIT 检查及受支持的截断检查均满足要求 | 可作为数据层证据，仍需实验和策略验证 |
| `research_only` | 缺来源或历史证据、样本不足，或当前执行器不支持截断检查 | 可继续研究，补齐证据后重新评估 |
| `failed` | 发现时点违规、未来依赖、无效表达式等明确问题 | 修复输入或表达式后重新检查；绑定快照计算会拒绝 |

后续已有 compute / auto-evaluate 接口继续传同一 `datasetSnapshotId`，无需新增第二套计算接口。完整报告包含 `expressionHash`、`sourceIds`、`qualification`、`pit`、`truncation` 和 `limitations`。截断子报告的 `passed` 只是该项检查通过，不代表完整数据报告为 `passed`。

### 检查边界和兼容性

- 截断检查复用现有表达式求值器，不调用外部数据。默认最多 3 个截断点，至少 10 个不同的有限 `symbol/date` 比较样本，且每个被选标的和截断点都需要有效比较覆盖。
- 检查有输入规模和估算计算量限制；超过限制返回 `unsupported`，不能当作通过。全空、NaN 或仅 warmup 返回 `insufficient_data`。
- 检查不能证明数据首次发布时间真实、历史修订完整、历史标的池无偏、复权口径正确，也不能证明策略具有预测力。缺少这些证据时应显示相应限制。
- 截断检查通过只能说明所抽取的截断点未暴露变化。它不能排除所有前视依赖，更不能代替跨尝试的封存测试集隔离。
- 外部 Python / SQL / 模型执行器尚未接入同等截断检查时，不获得这一项通过证据。
- 过去因默认值而被视为 `verified` 的数据，按新规则可能只能用于研究；依赖这类默认资格的晋级可能不再通过。这是纠正证据含义。旧报告不会凭空补齐缺失证据，应按同一候选版本重新检查和评估，保留旧记录供追溯。
- 当前普通行情连接器尚无经过验证的 PIT 来源证明接入，因此它们生成的快照保持 `research_only`；重新运行本身不会解除限制。后续必须为选定市场接入可核验的来源版本、公布/修订时间证据与可信适配器，再开放验证资格，不能通过手填 `verified` 恢复旧行为。

### 第 1 步验收标准

- 冻结快照后，绑定计算不回落实时连接器；同一输入产生可重复结果，报告可关联到精确快照和表达式。
- 注入晚于边界的数据、错误时间戳、重复/乱序日线及明确未来引用时，系统不能给出可信通过结论。
- 合法因果滚动因子可通过截断检查；未来标准化导致的历史输出变化和单侧信号消失可被比较器发现。
- 样本不足、全空和未支持执行器不会出现虚假的绿色通过；缺 PIT 来源证据的数据仍可明确标记为仅供研究。
- 用户能在工作台完成选快照、检查、计算、评估、回看证据；失败信息能定位原因。
- 第 1 步的验收止于数据与计算可信度；跨尝试台账与封存服务由下述第 2 步提供。

## 第 2 步：受控研究协议、实验台账与独立评估（已实现）

### Harness 与执行控制

- 每个现有项目可登记一套研究协议：假设、基准、停止条件、日线开发快照、标的、日期、固定收益天数和分组方法。协议修订产生不可变版本和指纹；有进行中的尝试时不能修订。停止条件与基准文字作为预登记事实保留，当前自动执行的是数值预算和数据/方法边界，不会把自由文本当成可执行规则。
- 因子计算、开发评估及已有回测服务在计算前登记候选和请求。失败、取消、超时与低分保留；实验执行成功 `completed` 与验证结论 `passed` 分别展示。候选版本由表达式/参数内容冻结，不能只靠可变名称解释历史结果。
- 项目总尝试预算覆盖计算、开发评估、回测和正式评估；正式评估另外消耗 `maxEvaluations`。预算在首版固定，跨模型、会话、协议版本及候选名称累计；SQLite 同步事务防并发超发。幂等键重试返回原尝试，不再计算或扣额；参数冲突拒绝。
- 异步因子提交可在界面轮询，默认尝试期限 120 秒。服务重启后保留记录，过期未完成任务变成 `timed_out`。取消不返还额度，迟到结果不能覆盖取消/超时终态。取消不是强制杀死所有底层计算；已开始的 DuckDB 开发因子值写入可能完成，但不能因此生成有效评估证据。正式结果、评估写入和实验终态受服务端租约检查。
- 已有因子和回测入口同样服从协议。受控项目仅运行内置日频 `qlib_expr` 与内置评估/回测 Provider；拒绝临时换快照、日期、标的、评估方法或 Provider。原始手工传值评估不可绕过。
- Agent 工具控制接在真实 Prime bridge / builtin 分发路径，包含 connector 和外部 MCP 分叉。项目身份取自持久工作流；受控研究只允许协议、台账、候选注册/查询、受控因子提交及少量计划/发现工具。Shell、Python、任意数据读取、旧评估工具和不明委派不可扩大这个工具面。无受控协议的旧项目仍可自由探索。
- 受控项目的旧 `final_holdout` 入口关闭，不能用新的 `backtestRunId` 获取“新的一次”独立验证。策略封存验证与自动晋级仍在第 4 步范围；本轮独立服务只评估因子预测能力。

### 研究管理界面

在量化工作台选择“研究管理”，并在“数据范围”选定一个具体项目：

1. 先在因子工作台注册候选并冻结开发数据快照，复制快照 ID。
2. 在研究管理登记假设、基准、停止条件、快照、标的、日期、评价方法与累计预算。已有协议时可查看全部版本并创建修订，不能覆盖旧版或增加额度。
3. 选择同项目候选，提交“开发数据 · 因子计算”或“开发数据 · 因子评估”。提交立即返回登记记录；页面刷新运行状态，展示累计使用量。
4. 展开实验查看冻结输入、协议、结果和失败原因；可取消进行中的尝试，或暂停项目以阻止新提交。开发计算成功不等于正式验证通过。
5. 独立评估服务可用且协议选定封存数据集后，才能提交正式评估。方法由封存数据集固定；服务未配置/失联、额度耗尽、项目暂停均明确显示原因并禁止提交。

“全部项目”只用于浏览范围，研究管理要求明确选择项目，避免误写默认项目。切换项目会中止旧页面请求、丢弃过期响应。列表同时显示已纳入台账的策略回测；当前提交表单专注因子流程。

### 独立封存评估服务

`src/runtime/research-program/sealed-evaluator.ts` 提供独立 HTTP 服务，原始封存数据只由评估主机持有。协议在创建时由服务端绑定封存数据内容指纹，同 ID 数据变化必须重新登记协议，旧协议不能静默评分新数据。研究进程只取得数据集名称/日期/固定方法/内容指纹，以及绑定尝试、协议和表达式指纹的聚合回执，不取得原始行情、因子序列或收益标签。

- 封存数据以 Ed25519 签名 bundle 导入；管理员在评估主机预置可信公钥，研究请求不能上传数据或自行声明来源资格。签名验证来源身份与内容完整性，不证明来源叙述为真；历史可用时间证明仍由可信数据提供方/适配器承担。
- 完整 payload 签名包含 `version: sealed-factor-dataset-v1`、`id`、`label`、`maxEvaluations`、`horizonDays`、`groupCount`、`dataset: BacktestDataset`，以及可选 `pointInTimeEvidence: {reference, issuer, statement: historical_availability_verified}`。外层为 `{keyId, signature, payload}`；签名输入为导出的 `canonicalSealedJson(payload)` UTF-8 字节。没有可信 PIT 证明及必要资格，即使签名正确，也只能获得 `insufficient_evidence`。
- 在调用内置表达式/统计评估前检查 PIT 与截断一致性。超出规模/复杂度限制直接停止，不把不支持当作通过。正向 Rank IC、统计门和至少 60 个日截面观测均满足，才产生预测能力门通过；这不包含组合增益、成本、交易可行性或盈利保证。
- 评估主机有独立 SQLite 台账，先扣额再计算，失败不返额。同一原始数据内容共享固定总额，重命名数据集、项目、候选、协议和重新建立研究进程数据库均不能在该评估库中重置。已用幂等键不会重新评分；评估进程中断后保留失败回执。管理员删除/复制评估库不属于受控 Agent 权限，也不是系统能防御的边界。
- 开发快照的全部行（包括标签预留和未选标的）不得覆盖服务目录中的任何封存日期区间。管理员应先登记、隔离封存数据再开始研究；系统不能追溯撤销研究员此前从外部接触过的信息，也不把多次自适应查询自动当成独立研究。

评估主机配置示例（文件路径相对该配置文件）：

```json
{
  "sqliteFilename": "state/sealed-evaluations.sqlite",
  "trustedPublicKeys": { "data-provider-2026": "<Ed25519 PEM 公钥>" },
  "bundleFiles": ["datasets/signed-daily-bundle.json"],
  "hostname": "127.0.0.1",
  "port": 8790
}
```

在隔离评估主机设置 `QUBIT_SEALED_EVALUATOR_CONFIG` 与至少 16 字符的 `QUBIT_SEALED_EVALUATOR_TOKEN`，运行 `bun run research:evaluator`。在研究主机设置 `QUBIT_RESEARCH_EVALUATOR_URL` 与匹配的 `QUBIT_RESEARCH_EVALUATOR_TOKEN`；远程连接要求 HTTPS，本地联调允许 loopback HTTP。当前评估服务每份数据库按单实例运行；启动会把遗留进行中尝试记为失败并保留扣额。生产应使用独立主机/容器账户、TLS 与持久磁盘；不要把 bundle 或签名私钥放进研究 Agent 可访问的目录。仓库不包含真实封存数据、密钥或伪造的验证种子。

### REST 与外部 Agent 接入

- `GET /api/v1/research-programs/:projectId`：协议、预算、全部尝试。
- `POST /api/v1/research-programs/:projectId/protocols`：`{spec}` 创建协议版本。
- `PATCH /api/v1/research-programs/:projectId`：`{status: active|paused}`。
- `POST /api/v1/research-programs/:projectId/attempts`：`{factorId, kind, idempotencyKey}`；`kind` 为 `factor_compute`、`factor_evaluate` 或 `sealed_factor`，返回 202。
- `POST /api/v1/research-programs/:projectId/attempts/:id/cancel`：取消。
- `GET /api/v1/research-programs/evaluator`：服务可用性与封存目录。

内置工具使用 `research.protocol.get/create`、`research.factor.run`、`research.attempt.list/cancel`。外部 Agent 可配置 stdio MCP：运行 `bun run research:mcp`，设置 `QUBIT_RESEARCH_PROJECT_ID` 和可选 `QUBIT_RESEARCH_API_URL`（默认 `http://127.0.0.1:3000`）。MCP 只暴露绑定项目的协议、候选注册/查询、尝试提交与取消，参数不能切换项目。后端持有实际执行任务，MCP 会话退出不会丢失台账。

当前应用 REST 是与既有工作区 API 一致的本机操作者接口，没有新增全应用身份认证或多租户隔离；不要把该端口作为无认证公网服务。MCP 工具边界不能限制外部 Agent 自带的 Shell 或浏览器。封存数据保密依靠独立评估主机的部署权限；任意本机代码执行能力与本地隐藏文件不构成数据隔离。单客户本机环境之外的租户权限仍在后续管理工作范围。

### 本步验收

本轮 20 个 Bun 测试文件共 202 项通过，覆盖真实迁移、并发额度、幂等冲突、协议不可变、跨项目封存额度、取消/过期/重启、因子真实计算与嵌套评估、回测登记与终态、内联回测前视检查、旧入口限制、Prime bridge connector/MCP 拒绝、签名篡改、无证明拒绝通过、服务版本漂移在扣额前拒绝、聚合回执绑定与原始数据拒绝。另有 9 项 Rust 回归通过，覆盖 task-local 项目/会话身份、并发和嵌套恢复，执行器不再用共享的“最后会话”作为权限依据。测试使用隔离临时目录和明确标注的合成样本，不写入实际研究库。

前端全量类型检查和生产构建通过，新模块格式检查通过；`cargo check -p qubit-app-server --offline` 通过，确认运行服务集成可编译。浏览器实际验收未完成：本机预览服务启动未获得执行授权，本地文件预览又被浏览器 URL 安全策略禁止；没有声称已取得桌面/窄屏截图或端到端界面验收。代码中已处理项目切换、失败/取消、预算、封存服务不可用及数据版本变化，仍应在可运行的预览环境复核交互与布局。仓库全量后端 TypeScript 检查仍有既有错误；本次修改文件没有剩余类型诊断。

## 第 3 步：已有因子库上的增量评估

复用现有相关性、暴露和评估能力，建立固定比较协议：表达式规范化；信号排序、相关性、覆盖和分阶段行为；收益相关、换手、衰减与成本敏感性；相同约束下加入现有组合的边际贡献。需要风格或行业中性化时使用有版本的分类与风险数据。

输出“已知重复”“证据不足”“值得进一步验证”等有证据的结论，并保留人工复核入口。避免只用相关系数或单次 IC 阈值自动判定新颖性。

**验收标准：** 对等价表达式、高度相近信号、风格代理、低相关但无收益贡献的预设样例给出合理区分；每个结论能回到同一快照、比较基准、方法和结果；加入组合的改善经过第 2 步的验证协议，而非在同一窗口反复挑选。

## 第 4 步：因子到策略的可复现闭环

连接已有因子注册、研究合同、`strategy.create_version`、`strategy.compose`、回测和 Strategy API 编译能力。明确每个环节使用的信号方向、标准化、中性化、组合权重、再平衡、订单限制与成本假设。需要接入客户引擎时优先实现适配和结果对账。

产物包含研究假设、因子版本、协议、数据快照、组合定义、策略代码或配置、执行假设与报告，支持导出和重新运行。

**验收标准：** 至少一个端到端日频研究案例可从登记假设走到策略候选与受控评估；预设的不合格案例在对应阶段停止并记录原因；同一产物在独立进程可复现关键指标；不能绕过数据资格、版本和验证规则直接进入下一状态。

## 第 5 步：统一因子、策略和证据的资产管理

沿用现有实体与存储，统一资产关系和状态视图：研究项目 → 协议 → 尝试 → 因子版本 → 组合/策略版本 → 评估 → 模拟运行。表达式、参数或数据变化产生新版本，已发布结论不被静默覆盖。

用明确状态区分草稿、研究中、待验证、通过验证、模拟运行、失效和退役；状态转换引用具体证据。原始事实不可被模型总结替换，失败结论带适用时期、市场和成本条件。不同客户、团队的私有资产按权限隔离。

**验收标准：** 任意策略结果能追溯到输入与全部实验谱系；可查看版本差异、恢复旧版本并定位过期证据；失败与退役资产可检索且不会丢失；无证据不能晋级；跨团队越权读取被拒绝。

## 第 6 步：模拟运行与持续验证

复用已有 paper / shadow 和晋级机制，把同一策略的输入、信号、目标仓位、订单和成交逐段对齐。持续记录数据变化、执行偏差、成本、容量和失效条件；触发退回验证、暂停或退役时留下证据。

**验收标准：** 在同一比较条件下，可将回测与模拟运行的差异定位到具体阶段；预设异常能触发相应状态规则；持续运行和恢复不会丢失研究版本、订单与评估关联；模拟证据不被当作实际成交证据。接入实盘应有单独的授权和运行流程，本路线图不会自动启用实盘。

## 如何验证环境本身的价值

第 1 至第 3 步完成后，用相同 Agent、相同 skills 和相同研究任务，对比普通 Python 环境与 Qubit 环境。比较严重数据/验证错误、重复候选、人工核查时间、计算成本和阻塞率，再分别关闭时点检查、实验约束、增量评估，观察效果来源。

每一步都先通过可复现的错误注入与真实研究案例，再扩大市场、频率和执行器范围。Qubit 的研究状态、权限与证据应独立于基础模型，使更换 Agent 后仍能继续同一个研究项目。
